# 네이버 데이터랩 쇼핑인사이트 TOP 500 수집 프로그램 기획서

## 1. 프로젝트 개요
- **목표**: 네이버 데이터랩 쇼핑인사이트를 활용하여 최신 데이터 동향 분석을 위한 인기 검색어(TOP 500) 데이터 자동 수집 프로그램 개발
- **운영 방식**: 매주 자동화 스케줄링(매주 토요일 아침 9시) 및 필요 시 사용자가 직접 실행할 수 있는 그래픽 인터페이스(UI) 동시 지원
- **타겟 URL**: [네이버 데이터랩 쇼핑인사이트](https://datalab.naver.com/shoppingInsight/sCategory.naver)
- **주요 타겟**: 식품 산업 동향 파악 (특히 1차 산물 위주)

## 2. 수집 대상 및 세부 조건
- **1차 카테고리**: `식품` (고정)
- **2차 및 3차 카테고리 (수집 대상 4개)**: `축산물(2차)`, `수산물(2차)`, `농산물(2차) > 과일(3차)`, `농산물(2차) > 채소(3차)`
- **조회 기간 (핵심 산출물: 총 8개의 TOP 500 데이터 세트)**:
  1. 실행일 기준 **최근 7일** (오늘 날짜부터 7일 전까지, 4개 대상 각각 1개씩 -> 4개)
  2. 실행일 기준 **미래 예측 7일** (작년 오늘 날짜부터 7일 후까지, 4개 대상 각각 1개씩 -> 4개)
- **사용자 조건 설정 (필수)**:
  - **연령**: `40대`, `50대`, `60대 이상` (항상 활성화)
- **결과물 형태**: 분석에 용이한 정형 데이터 포맷 (`.csv` 또는 `.xlsx`)

## 3. 기술 스택 제안 (10년차 관점)
- **개발 언어**: `Python 3.x`
- **핵심 라이브러리**:
  - **크롤링/브라우저 제어**: `Playwright` 또는 `Selenium` (동적 렌더링/페이징 처리용)
  - **데이터 전처리 및 저장**: `Pandas`, `datetime`, `dateutil` (정교한 날짜 계산용)
  - **스케줄링**: 운영체제의 `Cron` (Mac/Linux) 또는 `Windows 작업 스케줄러`, Python 내부 `schedule` 라이브러리
  - **사용자 인터페이스(UI)**: `Streamlit` (확정)
    *(데이터 시각화 및 웹 기반 제어 패널 구축에 최적화)*

## 4. 프로세스 설계 (User Flow & Data Flow)
1. **실행 분기 (Trigger)**:
   - 스케줄러에 의한 백그라운드 자동 실행 (매주 토요일 09:00)
   - UI를 통한 사용자의 수동 실행 (버튼 클릭)
2. **초기화 및 브라우저 실행**: UI 모드 시 화면 노출(Headed) 혹은 진행률 표시, 스케줄링 시 백그라운드(Headless) 기동
3. **조건 설정**:
   - 1차 분류 드롭다운 클릭 -> `식품` 선택
   - 연령 조건 체크박스 활성화 -> `40대`, `50대`, `60대 이상` 선택
4. **루프 프로세스 (총 8회 반복)**:
   - **대상**: [축산물, 수산물, 농산물>과일, 농산물>채소] × [최근 7일, 미래 예측 7일]
   - 각 조건에 맞게 2차 분류와 조회 기간 입력 후 `조회하기` 버튼 클릭
   - 데이터 로딩 대기
5. **데이터 수집 (Paging Processing)**:
   - 1페이지 데이터 스크래핑 -> `다음 페이지(>` 버튼 클릭 -> 로딩 대기
   - 25페이지(500위)까지 반복 수행하여 500개 데이터 추출
6. **데이터 후처리 및 병합**: 8개의 세트를 각각 명확하게 구분할 수 있도록 파일 분리 또는 통합 시트 내 구분(식별자 컬럼 추가)
7. **결과물 저장**: `results/YYYY-MM-DD/` 형태의 실행 일자별 전용 폴더를 자동 생성하고, 그 안에 `수산물_최근7일.csv`와 같은 직관적인 네이밍 컨벤션으로 파일들을 깔끔하게 정리하여 저장

## 5. 리스크 매니지먼트 및 대응 방안
- **이슈 1: 복잡한 날짜 계산 및 윤년 이슈**
  - **대응**: `dateutil.relativedelta` 등을 활용하여 작년 오늘 날짜를 정확히 산출하고 예외(윤년 2월 29일 등)를 안정적으로 처리.
- **이슈 2: UI 및 브라우저 컨트롤 충돌**
  - **대응**: UI 스레드와 크롤러 동작 스레드를 분리(Thread/Asyncio 활용)하여 UI 프리징(멈춤) 현상 방지.
- **이슈 3: 네이버의 봇 탐지 (Anti-Bot)**
  - **대응**: 페이지 이동 및 조회 버튼 클릭 사이에 난수형 딜레이(Delay) 추가.

## 6. 마일스톤 및 개발 단계
- **Phase 1**: 날짜 계산 모듈 구현 및 Playwright 기반 단일 조건(예: 농산물, 최근 7일, 연령 설정) 크롤링 PoC 완료
- **Phase 2**: 전체 8개 케이스 순회 로직 완성 및 예외 처리, 데이터 정제 기능 추가
- **Phase 3**: 사용자 편의를 위한 GUI/웹 UI (Streamlit 등) 연동
- **Phase 4**: 운영체제 스케줄러 등록 (매주 토요일 9시 자동 실행) 및 최종 QA 테스트
